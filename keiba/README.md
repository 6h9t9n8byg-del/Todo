# 競馬予想システム

過去のレース結果から**各馬の単勝勝率**を推定し、市場（単勝オッズ）と統合して
期待値を計算するシステムです。ウォークフォワード検証と馬券シミュレーションまで
一通り含んでいます。

```
keiba/
├── keiba/
│   ├── schema.py     入力データの定義と検証
│   ├── data.py       合成レースデータ生成器（動作確認・テスト用）
│   ├── features.py   特徴量エンジニアリング（リーク防止が最優先）
│   ├── grouping.py   レース単位のベクトル演算（softmax・正規化）
│   ├── models.py     条件付きロジット / LightGBM ランカー / 二値分類 + アンサンブル
│   ├── market.py     オッズ→確率の変換（控除率除去）とブレンド
│   ├── pipeline.py   学習〜校正〜予測の統合
│   ├── backtest.py   ウォークフォワード検証と馬券シミュレーション
│   ├── metrics.py    的中率・NLL・キャリブレーション
│   ├── report.py     HTML予想シート出力
│   └── cli.py        コマンドライン
└── tests/            リークテストを含む23件のテスト
```

## クイックスタート

```bash
pip install -r requirements.txt

# 1) 動作確認用の合成データを生成（約4年・3,360レース・40,298頭分）
python -m keiba generate --out data/races.csv --days 420 --horses 2200

# 2) ウォークフォワード検証（学習→次の90日を予測、を繰り返す）
python -m keiba backtest --data data/races.csv --step-days 90

# 3) 全履歴で学習してモデルを保存
python -m keiba train --data data/races.csv --out model.joblib

# 4) 出馬表を予測して HTML の予想シートを出力
python -m keiba split --data data/races.csv --entry-days 2 --races 3
python -m keiba predict --history data/history.csv --entries data/entries.csv \
                        --model model.joblib --html sheet.html
```

## 精度を高めるための設計

### 1. 「レース内の相対比較」として解く

各馬の勝率を独立に予測すると、レース内の合計が1になりません。ここでは全モデルが
**レース単位の softmax** を通り、確率が必ずレース内で合計1になります。
期待値計算・馬券選択・ケリー基準はすべてこの前提に依存します。

* **条件付きロジット**（多項ロジット）… 尤度 `Π p(勝ち馬)` を直接最尤推定。線形で
  安定しており、少データでも壊れません。
* **LightGBM lambdarank** … レース内の順位関係そのものを損失にします。
* **LightGBM 二値分類** … 勝ち/負けを学習し、レース内で正規化。

3つは誤り方が異なるため、**対数線形プーリング** `p ∝ Π p_k^{w_k}` で統合します。
重み `w` は検証データの対数尤度を最小化して解析勾配つき L-BFGS で求めます。

### 2. リークを構造的に排除する

競馬モデルで最も多く、最も致命的なバグが「未来の情報の混入」です。

* 馬・騎手・調教師・種牡馬の集計はすべて **現在行より前の行だけ** の累積
  （exclusive cumsum）で計算します。
* ターゲットエンコーディングは K-fold ではなく **時系列**（その時点までの成績を
  事前分布へスムージング）。学習時と推論時で手続きが同一になります。
* 事前分布にデータ全体の平均を使うと、それ自体が弱いリークになります。相対着順は
  定義上の平均 0.5、勝率は 1/出走頭数、スピード指数は 50 という**理論値**を使います。
* スピード指数の基準タイムも、**過去のレースのみ**から推定した条件別の平均です。
* 評価はランダム分割の交差検証ではなく、**ウォークフォワード**のみを提供します。

これは `tests/test_leakage.py` で機械的に検証しています。カットオフ以降の結果を
すべて破壊しても、それ以前の行の特徴量が1つも変わらないことを確認するテストです。

### 3. 特徴量（80列）

| 分類 | 内容 |
| --- | --- |
| スピード指数 | 走破タイムを条件別の基準タイムとの差に変換（50が平均、10が1SD）。過去5走平均・自己ベスト・直近・トレンド・ばらつき |
| 実績 | 勝率・複勝率・相対着順（過去全体 / 直近3走） |
| 条件適性 | コース別・距離帯別・馬場状態別・芝ダート別の成績 |
| ローテーション | 休養日数、長期休養明けフラグ、馬体重増減、斤量増減 |
| クラス | 平均出走クラス、自己最高クラス、今回のクラス変動（昇級/降級） |
| 人的要因 | 騎手・調教師の勝率と相対着順、騎手×競馬場、馬×騎手コンビ |
| 血統 | 種牡馬の相対着順、種牡馬×芝ダート・種牡馬×距離帯のスピード指数 |
| バイアス | 競馬場×条件ごとの枠順バイアス、脚質バイアス |
| 展開 | 過去の4コーナー通過順から脚質を推定 → 出走メンバー全体のペース圧力と、自分の脚質との相性 |
| メンバー相対 | 出走メンバーの平均・最高スピード指数との差、主要特徴量のレース内 z-score |

合成データでの重要度上位は `z_h_class_avg`（出走クラスのレース内 z-score）、
`z_h_rel_avg`（相対着順の z-score）、`h_surface_si`（芝ダート別スピード指数）、
`si_vs_field`（メンバー平均との差）で、**レース内で相対化した特徴量が上位を占めます**。
「絶対的な強さ」ではなく「このメンバーの中でどうか」が着順を決めるためです
（展開系は全80列中30〜60位程度で、寄与は小さめでした）。

### 4. 確率の校正（キャリブレーション）

順位学習のスコアをそのまま softmax に通すと確率が過信/過小になります。期待値は
確率の絶対値に依存するので、順位が合っていても確率がズレていれば損をします。

* **温度スケーリング** … 全モデルのスコアを検証データで温度補正
* **アイソトニック回帰** … 最終確率に残る単調なズレを補正。ただし採用可否は
  検証データ内の2分割交差検証で判定します（同じデータで当てはめて評価すると
  必ず改善して見え、実際には悪化するため）
* 検証期間の重みを決めたあと、**検証期間も含めた全データで再学習**します
  （早期終了で決まった本数を保持したまま。直近データは最も価値が高いので捨てません）

### 5. 市場（オッズ）の活用

単勝オッズは多数の予想の集約であり、単体の予測子として非常に強力です。ただし
そのまま `1/オッズ` を確率にすると、控除率（約20%）ぶん必ず過大評価になります。

* **power法**で控除率を除去します。`Σ (1/oᵢ)^k = 1` となる k を解くと k>1 になり、
  人気薄の確率が相対的に切り下げられます。これは「大穴が買われすぎて実力より
  オッズが低い」という**本命-大穴バイアス**の補正になります。
* モデル確率と市場確率を**対数線形ブレンド** `p ∝ p_model^w · p_market^(1-w)` で統合。
  重み w は検証データで最適化します（合成データでは w ≒ 0.05〜0.10、つまり市場が支配的）。
* モデルにオッズを特徴量として渡していないのは、**モデル単独の上積みを測れる**
  ようにするためです。オッズを入れるとモデルは市場を模倣するだけになります。

### 6. 評価とリスク管理

* 的中率だけでなく **NLL・Brier・キャリブレーション曲線**を必ず見ます
* 馬券シミュレーションは期待値しきい値を振ったグリッドで感度を確認します
* ROI は**レース単位のブートストラップで95%信頼区間**を出します。馬券の収益は
  分散が極めて大きく、点推定のROIだけを見るのは危険なためです
* 資金管理は**フラクショナルケリー**（既定 1/4）＋1点あたりの上限で破産を防ぎます

## 合成データでの検証結果

`python -m keiba backtest --data data/races.csv --step-days 90` の実測値
（3,360レース中、最初の420日を除く2,400レースがアウトオブサンプル）。

```
=== アウトオブサンプル精度 ===
モデルのみ         races=2400 top1=0.198 top3=0.479 NLL=2.2896 (baseline 2.4614) Brier=0.0735
市場(オッズ)のみ    races=2400 top1=0.326 top3=0.652 NLL=1.9285 (baseline 2.4614) Brier=0.0664
最終(ブレンド)      races=2400 top1=0.335 top3=0.652 NLL=1.9288 (baseline 2.4614) Brier=0.0662
```

* オッズを一切見ないモデル単独でも、等確率（baseline NLL 2.4614）を大きく上回ります
* 単勝的中率は市場 32.6% に対しブレンド 33.5% と、市場をわずかに上回ります
* 一方 NLL はほぼ同等で、**モデルの上積みは小さい**という結果です

馬券シミュレーション（均一100円、期待値しきい値ごと）:

```
 ev_threshold  n_bets  hit_rate     roi  roi_lo  roi_hi
         0.00     325    0.1692 -0.0231 -0.2636  0.2263
         0.05     165    0.1636 -0.0618 -0.3861  0.2982
         0.10      92    0.2065  0.1924 -0.3042  0.7134
         0.20      23    0.1304 -0.3870 -1.0000  0.2783
```

ROI がプラスに見える条件でも**信頼区間は必ず0をまたいでいます**。控除率20%を
安定して超えるのは、この程度の精度差では不可能だという読み方が正しいです。

なお合成データの生成器は「1番人気の勝率33.5%・複勝率66%・単勝オッズ中央値3.0」と、
JRAの実績値（概ね32%・63%・2.7前後）に近くなるよう調整してあります。オッズには
本命-大穴バイアスも埋め込んであり、power法がそれを実際に補正できることを
確認しています（オッズ帯別に見た予測確率と実勝率の平均誤差は、単純な比例配分の
0.0140 に対し power法は 0.0050 と 1/3 以下）。

## 実データを使う

`data/races.csv` を自分のデータに差し替えるだけで動きます。1行 = 1頭の出走記録で、
同じ `race_id` を持つ行が1レースを構成します。

| 列 | 説明 | 必須 |
| --- | --- | --- |
| `race_id` | レースID | ○ |
| `date` | 開催日 (YYYY-MM-DD) | ○ |
| `venue` | 競馬場 | ○ |
| `surface` | `turf` / `dirt` | ○ |
| `distance` | 距離(m) | ○ |
| `going` | `firm` / `good` / `yielding` / `soft`（良/稍重/重/不良） | ○ |
| `race_class` | クラス水準（1=未勝利 … 9=G1 のような数値） | ○ |
| `horse_id`, `horse_name` | 馬 | ○ |
| `draw` | 馬番 | ○ |
| `sex`, `age` | 性・年齢 | |
| `jockey_id`, `trainer_id`, `sire_id` | 騎手・調教師・種牡馬 | |
| `weight_carried`, `body_weight` | 斤量・馬体重 | |
| `odds` | 単勝オッズ（無い場合はモデル単独で動作） | |
| `finish_pos`, `finish_time` | 着順・走破タイム（**学習に必須**） | 学習時 |
| `corner_pos`, `last_3f` | 4コーナー通過順・上がり3ハロン | |

予測対象の出馬表は、結果列（`finish_pos` など）を空にして `--entries` に渡します。
欠損列があっても自動で補完されますが、`finish_time` が無いとスピード指数が使えず
精度は大きく落ちます。

実データで精度を上げるための追加候補（未実装）:

* 調教タイム・追い切り評価（実データでは有力な特徴量）
* 馬場差（同日同条件の時計から算出する日次のトラックバイアス）
* 複勝・馬連・三連複への拡張（Harville近似やPlackett-Luceモデルで着順分布を導出）
* 直前オッズの時系列（オッズの動きは情報を含む）

## 注意

* 本システムは**予測の研究・学習を目的とした実装**です。的中や利益を保証しません。
* 公営競技には約20〜25%の控除率があり、長期的な収支はマイナスになるのが通常です。
  上のバックテストが示しているのも「控除率を超えるのは容易ではない」という事実です。
* 合成データでの結果は、生成器の仮定（市場が展開を織り込まない、など）に依存した
  ものであり、実際の馬券が利益を生む根拠にはなりません。
* 馬券の購入は20歳以上、自己責任で、余裕資金の範囲で行ってください。
